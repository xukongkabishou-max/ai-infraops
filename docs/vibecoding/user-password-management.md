# 用户密码管理

3001 后台的“用户管理”提供用户列表和“修改密码”。当前仍处于启用状态的超级管理员可以重设其他普通账号及自己的密码，无需旧密码；`admin` 账号的密码仅由 admin 本人修改，避免其他超级管理员通过接管 admin 绕过明文访问限制。新密码输入两次确认，保留首尾空格，拒绝全空白密码；bcrypt 限制为最多 72 个 UTF-8 字节，避免截断造成密码碰撞。

只有数据库中用户名严格为 `admin` 且仍为启用的超级管理员，才能通过“查看密码”看到已记录的明文。在 admin 的改密弹窗中，新密码以明文显示；其他超级管理员的输入框使用密码类型。普通运维、研发和其他超级管理员均不能调用明文读取接口。前端按钮仅是展示控制，后端每次操作会再次检查数据库身份与权限。

登录密码继续存储为 bcrypt 哈希。通过新接口重设的密码同时使用 AES-GCM 加密存储，附加数据绑定目标用户 ID，使用现有中间件凭证加密密钥。普通用户列表不返回哈希或密文。明文读取必须与当前哈希校验一致，防止外部改库后展示陈旧密码。历史账号只有哈希时无法还原，显示“未记录，重设后可查看”；不会猜测或覆盖现有密码。

修改密码与递增 `rbac_users.auth_version` 在同一 MySQL 事务中完成。登录时保存哈希所属的版本号，所有会话加载都检查当前数据库版本，因此原有用户端、后台以及审批详情页会话均失效，旧密码并发登录产生的旧版本 token 也不可用。旧的未带版本会话按版本 0 兼容。admin 修改自身密码后退出登录，使用新密码重新登录。

接口：`PUT /api/rbac/users/{id}/password`（`new_password`、`confirm_password`）；`GET /api/rbac/users/{id}/password`。两个接口都要求后台会话；读取接口额外限制 admin 身份。改密结果不返回密码，读取结果禁止缓存，密码不写入浏览器持久存储。修改、明文查看分别记录 `user_password_reset` 和 `user_password_view` 审计事件，只记录操作者、目标账号和操作结果，不记录密码或哈希。输入校验错误不回显提交内容。

数据库增量迁移：`021_user_password_management.sql`，增加会话版本、加密密码副本及修改时间，并登记权限点。部署时先执行此迁移，再重启后端。迁移不修改现有密码，不主动使未改密账号掉线。
