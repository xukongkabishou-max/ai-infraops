# 用户新增与编辑

后台用户管理页新增“添加用户”和“编辑”。仅当前启用且保留超级管理员标记的 admin 可调用新增/编辑接口，其他超级管理员不能通过伪造前端状态操作。已有改密和 admin 明文查看接口保持原权限边界。

新增用户支持“普通 RD”“超级管理员”两个角色，默认普通 RD。密码默认用密码学随机源生成 8 位，包含大小写字母、数字及符号；勾选自定义后可填写至少 8 位且不超过 72 个 UTF-8 字节的密码。创建成功在 admin 的列表中立即显示初始密码，数据库保存 bcrypt 校验哈希及绑定用户 ID 的 AES-GCM 密文，明文不进入审计日志。

新增时服务端写入 added_at、added_by、added_by_name，不接受客户端指定创建人。迁移 027 仅添加可空字段，不回填已有账号；编辑也不改写这些字段。已有运维角色保持不动，列表标识为历史角色；管理员主动编辑后使用表单选定的 RD 或超级管理员角色。

编辑可修改账号名、名称、角色及启用状态，保存后递增 auth_version，使原用户端/后台会话失效；不会修改密码。内置 admin 不允许改名、禁用或降权，编辑自己的显示名称后也需重新登录。

接口：POST `/api/rbac/users`，PUT `/api/rbac/users/{id}`。用户、角色关系与密码记录在一个数据库事务内提交，返回成功前回查哈希/密文；重复账号返回冲突。列表新增角色、添加时间和添加人，不返回密码明文。

验证涵盖两种角色的随机/自定义密码创建、元数据不回填、编辑不改密码、会话失效、事务回滚、内置 admin 保护及禁止非 admin 操作；实际测试账号完成后删除。
