# RBAC 权限与安全审计

## 角色边界

当前先固定三个系统角色：

| 角色 | 3000 用户控制台 | 3001 后台管理 |
| --- | --- | --- |
| `super_admin` | 全部功能 | 全部功能 |
| `ops` | 机器信息、业务系统、中间件系统、监控预留 | 允许访问，并拥有当前全部管理权限 |
| `rd` | 仅业务系统和中间件系统 | 禁止登录 |

机器信息页包含主机资源、Linux 账号和数据库账号等内部信息，因此不向 `rd` 开放。业务系统页的 NodePort、镜像和 Pod 环境变量 Key，以及中间件系统页的 Nacos 配置目录和脱敏配置结构，允许 `rd` 使用。

## 开发测试账号

`015_rbac_authorization_audit.sql` 创建以下本地开发测试账号：

```text
csk / csk              角色：ops
jiangjun / jiangjun    角色：rd
```

这些是开发环境初始口令，部署到共享或生产环境前必须修改或删除。

## 鉴权链路

登录请求的 `client_type` 只接受 `user_web` 和 `backend_admin_web`。登录 3001 时，后端额外强制检查 `admin:console:access`，因此修改请求参数不能绕过后台准入。

3000 使用登录响应中的 `menus` 和 `permissions` 共同生成导航。前端菜单隐藏只负责交互体验，所有受保护 API 仍在 FastAPI 依赖中校验会话类型和权限码。机器、RBAC、K8S、Nacos 和中间件管理接口不能匿名访问。

## 安全审计

`rbac_audit_events` 统一记录登录、会话恢复、鉴权拒绝和已认证 API 请求。记录字段包括：

- 请求 ID、时间、用户、角色快照和客户端类型
- HTTP 方法、路径、状态码、结果和权限码
- 来源 IP、User-Agent 和不含秘密的失败原因

审计不保存请求体、密码、Token、kubeconfig、中间件凭证和接口响应内容。审计写入失败不会阻断业务请求，但会写入后端错误日志。拥有 `audit:list` 的后台账号可以在 3001 的“审计日志”页面筛选和分页查看记录。

## 初始化与验证

在项目根目录执行：

```powershell
npm run init:mysql
npm run dev:rbac-api
```

验证重点：

1. `csk` 可登录 3000 和 3001，并能查询审计记录。
2. `jiangjun` 登录 3000 后只显示业务系统和中间件系统。
3. `jiangjun` 登录 3001 返回 `403`。
4. `jiangjun` 直接请求机器资源接口返回 `403`，匿名请求受保护接口返回 `401`。
