# 用户控制台静态功能骨架

日期：2026-07-27

## 背景

本次先不完整实现后端能力，只在普通用户控制台 `apps/admin-web` 中搭出后续功能的信息架构和静态页面。已有真实机器指标能力继续保留：登录后仍可通过 FastAPI 查询已添加 node-exporter 主机，并展示 CPU、内存、根目录磁盘使用率。

## 本次编码操作

- 将普通用户控制台登录后的单一“机器资源信息”页面扩展为左侧模块导航。
- 新增 4 个侧边功能栏：`机器信息管理`、`业务系统管理`、`中间件系统管理`、`监控系统集成`。
- `机器信息管理` 拆成 3 个子页面：`环境 API 地址`、`机器账号列表`、`中间件账号获取`。其中 `环境 API 地址` 只展示地址信息，不在页面里直接执行查询。
- `业务系统管理` 拆成 4 个子页面：`服务 NodePort`、`镜像 tag`、`GPU 模型显存`、`环境变量 key`。
- `中间件系统管理` 拆成 2 个子页面：`Nacos key 获取`、`数据库可用性校验`。
- `监控系统集成` 中预留 Prometheus、Loki、告警中心、SLO 守护入口。
- 所有静态示例 IP 均使用文档示例网段或占位 API 路径，避免把真实环境信息写入源码和文档。
- 账号列表当前只展示脱敏密码占位，不写入真实账号密码。

## 后续接入边界

- 环境 API 地址：后续确定是手动维护还是后端自动同步；页面侧只负责让研发查看这些地址。
- 机器与中间件账号：后续通过 Linux 相关 API、中间件管理 API 获取，页面侧只负责对授权用户展示。
- 业务系统服务信息：后续通过 K8S API 获取 NodePort、镜像 tag 和环境变量 key。
- GPU 模型显存：后续通过 dcgm-exporter 和 K8S workload 关联数据聚合。
- Nacos 配置 key：后续由前端传环境和服务信息给后端，后端请求 Codex，再通过 skill 获取配置并隐藏所有 value 后返回 key。
- 数据库可用性校验：后续由后端脚本模拟最小读写闭环，不在前端直接连接数据库。
