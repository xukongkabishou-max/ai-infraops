# Value 查看审批

业务系统管理和中间件系统管理各提供“我的审批记录”。环境变量按单个容器的单个 Key 申请。Nacos 必须填写页面脱敏结构的行号，只授权该行对应的一个标量值；弹窗回显对应配置路径和原文行号。两种申请均无需理由。后端兼容历史理由，新申请默认留空。

申请成功后、用户记录及后台记录均提供“审批详情”和“复制审批链接”。直达地址为用户端 `/approvals/{申请ID}`，例如 `http://localhost:3000/approvals/123`。链接只包含 ID，不携带账号、会话或任何数值。未登录时在该详情页登录，地址保持不变；申请人可看自己的状态与有效快照，具备当前 `admin:console:access` 和 `value:approve` 权限的管理员可查看申请并审批，其他用户返回 404。管理员仍不能通过详情页读取他人的具体值，不能自批申请。

详情页使用用户端会话。管理员若只登录了 3001 后台，在 3000 详情链接中需登录一次。该页面的审批操作复用原有审批逻辑和审计中间件，审批权限每次从数据库重新校验。

申请弹窗的“关联上线单（选填）”可填写上线单号和发布版本 / Commit ID，两项随申请保存，在用户端、详情页和后台展示。链接可附在上线工单中，长期追溯审批元数据；不会延长具体值的查看有效期。

生产部署时可给两个前端设置 `NEXT_PUBLIC_APPROVAL_PORTAL_URL=https://运维平台域名`，用于生成统一的分享链接。未配置时用户端使用当前浏览器地址；本地后台从 3001 指向同一主机的 3000，其他部署端口默认保持同源。HTTP 局域网页面不支持浏览器剪贴板接口时会显示可选中复制的链接文本。上线后应确保该地址可被审批人访问。

后台“审计日志”下方的“Key 查看审批”统一查看申请人、类别、环境、目标、申请时间及审批结果。审批权限为 `value:approve`，初始化授予 `ops` 和 `super_admin`。不能审批自己的申请。管理员可同意或拒绝并填写备注。

同意时读取源服务当前值并加密保存快照。环境变量记录实际采集的 Pod、容器及 Key；Nacos 仅保存所选行的单个值，以及配置路径、结构行号和原文起止行。采集失败时保持待审批，允许重试。默认有效期 60 分钟，可选 5 至 1440 分钟，从采集完成时间开始计算。重复审批通过数据库条件更新保护。

Nacos 使用 PyYAML 的语法树源位置构建对应关系。YAML/JSON 均规范化展示，每个标量单独一行，注释及原值不会进入预览；结构行号通过 JSON Pointer 绑定原文位置，不直接按相同行号截取原文件。数组按索引区分，多行字符串作为一个值授权；对象、数组容器及空集合不能整组授权。重复 Key、复杂 Key、YAML 别名与合并引用拒绝解析。

预览版本使用带服务端密钥的 HMAC，绑定实例、Namespace、Group、Data ID、格式及完整原文。提交时重新读取并校验版本，服务端推导并存储行号对应的路径。审批时再次校验版本、路径及原文位置。注释、空行或任何原文变化都会要求重新获取结构并申请；不自动将旧授权套用到新配置。读取快照时还校验授权范围与快照的绑定。

申请人只能查询自己的记录和读取自己的已批准快照。接口每次读取都检查当前账号、角色权限、源实例状态及 Namespace 白名单；服务端阻止过期读取，前端自动隐藏到期值。显示申请、审批、采集及到期时间（接口 UTC，页面本地时间）。审批列表不含明文，快照使用 AES-GCM 加密且附加数据绑定申请 ID，响应禁止缓存，审计日志仅记录操作元数据。

已展示的值无法从用户自行复制的副本中收回；有效期控制本系统中的后续访问，不会实时更新快照。

数据库变更：`services/backend/sql/018_value_access_requests.sql`、`019_nacos_line_scoped_approvals.sql`、`020_approval_release_context.sql`。019 将旧整份 Nacos 配置记录标记为失效并清除其加密快照，环境变量申请不受影响；020 幂等添加上线单号及发布版本字段。接口也独立阻止旧授权，不能通过旧的申请 ID 读取全文。已有环境只执行增量迁移，避免重跑初始化脚本重置现有账号。

验证：`python -m pytest tests`，以及两个前端的 TypeScript 和新增组件 ESLint 检查。测试覆盖两类申请、用户隔离、未审批拒绝读取、非管理员拒绝审批、自审批限制、过期、权限撤回、采集失败、加密、快照绑定、Nacos 行号与路径映射、版本变化、重复 Key 及旧全文授权拦截。
