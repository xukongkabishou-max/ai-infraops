# API 性能与请求追踪

历史列表请求是 `GET /api/value-requests?category=environment&page=1`（Nacos 使用 `category=nacos`）。浏览器默认请求当前前端的 `/api`，Next.js 再转发到 `BACKEND_RBAC_API_URL`；这与 HTTP_PROXY/HTTPS_PROXY 出站代理不同。PyMySQL 使用数据库 TCP 连接，不读取这些 HTTP 代理变量。Network 中若设置了 `pre` 等过滤词会隐藏该接口，应清空过滤或搜索 `value-requests`。

应用数据库现在通过 SQLAlchemy QueuePool 复用 PyMySQL 连接，保留原来的字典游标与显式事务接口。每个进程、每个数据库独立建池，默认保留最多 12 个连接、不使用临时溢出连接，等待连接不超过 5 秒，连接存活 300 秒后重建。这样并发峰值过后不主动销毁容量内的连接，避免下一批再次建连。借出时检查连接可用性；归还时回滚残留事务并关闭仍打开的游标。执行期间断线会使连接失效，不自动重放写操作。连接池耗尽或连接中断返回通用 503，不返回数据库凭证或 SQL 参数。服务正常关闭时释放空闲连接。

配置项：`MYSQL_POOL_SIZE`、`MYSQL_POOL_MAX_OVERFLOW`、`MYSQL_POOL_TIMEOUT_SECONDS`、`MYSQL_POOL_RECYCLE_SECONDS`。连接上限是每进程的上限，多 worker 部署需要累计计算。Redis 客户端原本已有连接池，现在使用 GETEX 合并会话读取与续期，减少一次网络往返；旧版本 Redis 不支持该命令时自动回退到原有 GET/EXPIRE。密码版本检查仍在数据库执行，失效会话仍会被删除。

历史列表总数和分页数据共享一次连接借用，管理员的两项实时权限检查合并为一次查询；用户身份、密码会话版本及角色权限仍实时核对，不缓存授权结果。审计写入在线程池中执行并等待完成，避免阻塞事件循环；不通过省略审计或延迟落库来缩短响应时间。

前端自动刷新在上一次请求结束 15 秒后调度，隐藏标签页暂停自动查询，切换筛选或离开页面会取消前端请求，防止固定间隔叠加慢请求。

响应头提供 `X-Request-ID`、`X-Response-Time-Ms` 和 `Server-Timing`。Network 的 Headers / Timing 可查看总耗时、连接获取、物理建连、SQL、连接归还、Redis、审计耗时，以及 SQL 次数、新建连接数。日志记录相同的数值和请求 ID，可按 ID 关联审计事件。只记录聚合耗时，不记录 SQL 正文、参数、token 或业务密码。`db_connect` 包含在 `db_acquire` 中，`audit` 也包含其数据库时间，这些子项不能直接全部相加。

2026-09-09 优化前实测：单次 MySQL 建连约 262–1276 ms，同连接查询约 51–54 ms；历史列表单次请求约 2.81–6.08 s。无数据库访问的路由对比中，直连后端中位数约 3.1 ms，经过本机 Next.js 转发约 7.4 ms。本机转发并非秒级延迟的主要来源。数据库位于公网，网络往返和数据库本身的波动仍会影响结果。

最终配置下，经 3000 前端转发的串行历史查询中位数为 982 ms（首轮包含一次新连接，最慢约 2.68 s）；20 并发建池预热后，重复一批 20 请求全部返回 200，中位数 1210.5 ms、P95 1502 ms、新建连接 0。前一轮 45 个成功响应的请求 ID 均在安全审计中匹配到记录。冷启动与公网网络波动仍应单独看待，不能把预热后的数据视为每次请求的耗时承诺。
