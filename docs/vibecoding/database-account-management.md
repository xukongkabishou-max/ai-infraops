# MySQL / Doris 账号管理

入口：后台中间件资源信息 -> 数据库账号管理。仅账号名严格等于 `admin`、数据库中仍处于启用状态且拥有超级管理员标记的用户可用。所有新接口同时要求后台会话，并实时查询用户身份；其他超级管理员也不能访问。用户端不增加此模块。

## 操作

- 选择 MySQL 或 Doris 实例后手动查询账号，不自动遍历远端实例。分页显示账号、Host、最后登记密码、登记时间、到期时间和状态；可按账号筛选，导出当前页 CSV。
- 远端密码哈希不能恢复成明文。已加密托管的密码在服务端解密后仅返回给 admin；未登记的显示“待手动添加”。手动登记只维护密码记录，不修改源数据库密码。
- 新建账号必须指定新用户名。权限表单默认勾选“默认对所有库表授权”和“所有库表只读”；也可切换到特殊库表模式，分别选择库级全部表、单表及其读写权限。默认不勾选创建库表及临时表权限，管理员明确勾选后才增加 DDL 权限。默认密码使用密码学随机源生成 8 位，保证大小写字母、数字和符号；也可指定 8-128 位密码。
- 新建权限按每个库或表分别选择只读或读写，允许同时设置 A、B 库全部表只读，以及 C 库 d、f 表读写。库名旁“全部表”表示数据库级授权，包含以后新增的表；表级授权可跨库多选。整库只读允许个别表额外读写，整库读写不能把某张表限制成只读。MySQL 只读为 SELECT，读写为 SELECT/INSERT/UPDATE/DELETE；Doris 对应 SELECT_PRIV 或 SELECT_PRIV/LOAD_PRIV。默认不授予 DDL；勾选创建库表及临时表权限后，MySQL 额外授予 CREATE、ALTER、DROP、CREATE TEMPORARY TABLES，Doris 额外授予 CREATE_PRIV、ALTER_PRIV、DROP_PRIV。特殊模式的 DDL 按所选数据库生效。
- 克隆复制申请当时的直接权限、角色及 MySQL 默认角色。源账号保持不变。Doris 无法无歧义解析的权限类型会拒绝克隆，不降级成全库权限。
- 默认永久，也可设置 1-3650 天。平台记录账号绝对到期时间，并设置数据库原生密码到期策略。历史密码在到期后仍保留，但不代表它仍能登录。

## 结果确认

账号列表的“库表权限”默认折叠，展开时单独查询数据库当前授权，按库、表显示只读或读写。进入“编辑权限”会再次获取当前版本，支持新增、撤销、升级、降级以及清空直接库表读写授权，不修改账号密码。自动生成的密码仍在创建成功区和账号列表向后台 admin 明文展示。

权限编辑使用 `/{实例ID}/permissions` 的 GET/PUT 接口，请求每项为 `{database, table, access}`；整库必须明确传 `table: null`，单表传表名。缺失 table 字段拒绝处理，避免误扩大范围。原创建请求的统一 access 仍兼容；新页面给每项发送独立 access。

编辑以当前完整授权和账号标记生成 HMAC 版本，执行前重新核验，过期版本返回冲突。先计算最小授权/撤销差异，再执行并完整回查。每次修改持久保存独立操作编号、修改前后授权、操作人和状态，同一实例账号通过唯一占用键串行处理。失败时尝试恢复原授权并回查；无法确认则保留待核验状态，可查询、重新核验或恢复修改前权限，不能宣称已成功。权限操作接口为 `/permission-operations/{UUID}`。

仅普通的直接库表读写权限可通过简化编辑器维护。全局、角色继承、列级、转授及其他复杂权限显示来源并拒绝用简单读写选择器覆盖；不把仍通过角色拥有的权限显示成已撤销，也不修改共享角色或数据库管理账号。MySQL 整库授权会根据 `partial_revokes` 设置处理库名通配字符，避免 `_` 或 `%` 匹配额外数据库。

源数据库的账号 DDL 不能与平台数据库组成同一个原子事务。模块使用持久操作编号、权限回查和补偿撤销完成结果闭环：

1. 操作编号与请求摘要绑定。同一编号重试返回原结果，不重复执行；同一编号用于不同请求返回冲突。
2. 先检查当前数据库账号的授权能力及目标账号是否已存在，再保存加密密码和创建记录。
3. 新账号带 `infraops-managed:<记录ID>` 标记，保存目标权限后逐条授权。
4. 回查标记、完整权限和已保存密码。只有核验通过且确认时间持久化后才返回 `created=true`。
5. 失败时只撤销具有本次标记的新账号，并回查账号确实不存在。不能确认源端结果时保留 `uncertain` 状态，不声称已撤销或已成功。
6. 管理员可按编号查询结果、重新核验，或撤销未完成创建。重新核验不补执行授权 SQL。页面中断后保存的只有操作编号，密码不写入浏览器存储。

操作接口位于 `/api/admin/database-accounts/operations/{UUID}`，提供 GET 查询和 POST `/verify`、`/rollback`。账号创建位于 `/{实例ID}/accounts`；接口请求和验证错误不回显密码或源 SQL。审计保留操作、实例、账号及授权范围，不记录密码。

## 到期处理

后台每 30 秒扫描平台中已托管且到期的账号，使用行锁、SKIP LOCKED 和租约避免两个后端重复领取。执行前核对实例地址指纹和账号管理标记，防止实例改绑或同名账号重建后误操作。

MySQL 使用 ACCOUNT LOCK 阻止新登录。Doris 2.1 无显式 ACCOUNT_LOCK，使用销毁的随机新凭证使原密码失效，保留账号及历史密码；不会删除用户或业务数据。已建立的数据库会话不会被主动终止。处理失败会记录错误并重试。平台停止时由数据库原生密码期限提供到期限制，平台恢复后继续处理待到期记录。

密码期限以原生数据库策略为准，绝不把缺失的托管记录当成永久。MySQL 使用 password_last_changed 的数据库时间戳，加 password_lifetime（空值继承 global.default_password_lifetime）计算；password_expired 标记优先表示已过期。Doris 2.1 通过 `SHOW PROC '/auth/<user@host>'` 获取 expiration_seconds 和 password_creation_time，DEFAULT 使用全局天数，NEVER 才表示永不过期；格式化起算时间由同一连接的 UNIX_TIMESTAMP 转回 UTC。仅查询当前页最多 20 个账号，并一次批量转换时间。

页面和导出分别提供“密码到期时间”“平台停用时间”；当前页没有平台停用计划时隐藏后一列。来源接口不支持、读取失败或缺少起算时间时显示未知，不能显示永久。密码到期不意味着账号被删除；记录的密码只代表最后登记值，不能证明仍可登录。

## 禁用与删除

仅后台 admin 可用。按钮先打开操作说明弹窗，再进入“再次确认”弹窗；必须输入完整 `user@host` 标识才能提交。API 同时校验确认身份、账号状态版本、实际管理权限和管理账号保护，不只依赖前端。内置 root/admin、MySQL 系统账号及当前实例连接凭证对应账号不能禁用或删除。

MySQL 禁用使用原生 `ALTER USER ... ACCOUNT LOCK`。Doris 2.1.7 明确不支持 ACCOUNT_LOCK，禁用改用 `PASSWORD_EXPIRE INTERVAL 1 SECOND`，保留账号、授权和原密码；回查密码已过期并留出原生毫秒精度余量后才确认成功。禁用不强制断开已有连接。Doris 禁用会覆盖原密码有效期，这一点在确认弹窗中显示。恢复使用需管理员在数据库中解锁或重新设置期限，此版本不提供启用按钮。

删除使用 DROP USER，随后回查账号确实不存在才返回成功；不删除业务库表，平台审计及历史密码记录保留。如果账号随后在外部被同名重建，页面标记“同名新账号”，旧账号密码、状态和停用计划不会套用到新账号，重新登记密码后作为新记录管理。

操作接口：GET `/{实例ID}/accounts/action-preview`，POST `/{实例ID}/accounts/actions`。请求包含独立操作编号、action、user_identity、confirm_identity、revision。同一编号重试仅返回原结果，不重复执行；结果不明确时返回待核验。GET `/account-actions/{UUID}` 查询持久结果，POST `/account-actions/{UUID}/verify` 只读核验源端结果，不重发禁用或删除 SQL。权限编辑与账号禁用/删除使用同一数据库咨询锁串行执行，存在待核验权限操作时阻止删除。

增量迁移 026 保存禁用/删除操作、账号身份指纹和确认结果。`python scripts/smoke_database_account_actions.py --development-only` 验证两次确认契约、旧状态拒绝、禁用后新登录失败、密码记录保留、删除启用/禁用账号、原表保留、重复请求、root 保护，并清理全部测试对象。

## 性能与存储

新模块的外部 MySQL/Doris 连接池与平台数据库池分离，每组连接凭证保留最多 2 个连接，无额外溢出，等待上限 3 秒，连接 5 秒，读写 10 秒。连接复用时检查存活，120 秒回收；空闲池清理，最多保留 24 组。所有源端操作运行于同步接口线程，不阻塞事件循环。授权循环最长 120 秒，不对写 SQL 自动重试。

实例元数据、密码记录和操作查询只读平台数据库。账号列表只访问选定的实例，库表列表按展开动作加载；未选择实例时不连接远端。密码以 AES-GCM 保存，AAD 绑定原实例和账号，快照禁止缓存。相同地址的共享数据库使用同一账号指纹约束，避免跨环境入口重复创建或密码记录分叉。

增量迁移：022 创建托管账号表，023 增加操作编号、目标权限和确认时间，024 增加物理实例账号唯一约束，025 新建权限变更操作记录及账号占用键。已有环境只执行未应用的增量迁移，不重新初始化用户表。

## 验证

运行 `python -m pytest`。明确指定 `python scripts/smoke_database_accounts.py --development-only` 才执行真实联调；脚本硬性核对开发实例 ID 和地址，每次使用唯一 mock 库表、账号和角色，并在 finally 中清理。

联调覆盖只读、读写、单库与跨库多表、自建、直接权限及角色克隆、随机/指定密码、永久/限期、到期拒绝新登录、重复请求返回原结果、禁止覆盖已有账号。非开发环境仅执行只读权限盘点，未做写语法试验。

`python scripts/smoke_database_permissions.py --development-only` 在开发 MySQL/Doris 的三个独立 mock 库上验证混合整库/单表授权、新增表继承、只读升级、读写降级、新增/撤销表、删除整库授权、清空权限、过期版本冲突及重复请求。测试保持密码不变，finally 清理测试账号、库表与权限操作记录。

语法依据：[MySQL SHOW GRANTS](https://dev.mysql.com/doc/refman/8.0/en/show-grants.html)、[Doris 2.1 GRANT](https://doris.apache.org/docs/2.1/sql-manual/sql-statements/account-management/GRANT-TO/)、[Doris CREATE USER](https://doris.apache.org/docs/3.x/sql-manual/sql-statements/account-management/CREATE-USER/)。最终以已验证的实例版本行为为准。
